Part one

What actually changed

Scope

Three new inputs into production

01

Generated code

Assistants now draft a material share of what we ship — including the dependency list. The model picks the package; nobody chose it.

02

Autonomous agents

Agents read tickets, open pull requests and run commands — holding real tokens, on real repositories, at machine speed.

03

Models and tools

Weights, datasets and MCP servers pulled from public hubs — executable artefacts, with far less provenance than a package.

None of these are bad. All three bypass the review path we built for human-authored code.

Three consequences

Approval becomes a formality — the diff is too large and arrives too often to read closely.

Confidence rises as scrutiny falls — studies find assistant users trust generated code more than it deserves.

Provenance is lost — six months on, nobody can say which lines a model wrote, or why.

Part two

How it reaches production

Threat model

Two problems, not one

 

Insecure by accident

Adversarial by design

What it is

A model reproduces a weak pattern, a stale API, or a package that does not exist

Instructions hidden in content the model reads — issues, docs, web pages, config files

How we find it

SAST, dependency scanning, code review — the tools we already run

Egress monitoring, tool-call audit, provenance checks — mostly not deployed

Who is targeted

Nobody — it is a defect, distributed at scale

Us, specifically — the payload is written for our stack

Maturity of defence

Understood — existing controls mostly transfer

Unsolved — no complete mitigation for prompt injection

Prompt injection is LLM01 — the top entry in the OWASP Top 10 for LLM Applications.

Privilege

The agent holds the credentials

97%

of organisations that suffered an AI-related breach had no proper AI access controls in place.

An agent is a confused deputy by construction: it cannot reliably tell our instructions from instructions embedded in the data it reads.

Non-human identities now outnumber human ones, and they rotate less, expire later, and are scoped more broadly.

The design-review question is blast radius: if this agent were fully attacker-controlled, what could it reach before anyone noticed?

Source: IBM Cost of a Data Breach Report 2025 (Ponemon Institute).

Provenance

Models and tools are dependencies too

We download executable artefacts from public hubs, on trust, with less scrutiny than we give an npm package.

Weights

Serialised model formats can execute code the moment they are loaded. Malicious models have been found published on public hubs.

Datasets

Fine-tuning data is rarely inventoried. Poisoning is cheap, persists in the weights, and survives every later evaluation.

MCP servers and tools

A tool description is untrusted text the agent obeys. A server can change its behaviour after approval — and usually nobody re-checks.

The question is the same one we ask of any dependency: where did it come from, who can change it, and would we know if they did?

04

Part four

What good looks like

Controls

Five controls that matter

01

An inventory of every model, agent and tool

What is deployed, what it can reach, and who owns it — extending the SBOM to weights and MCP servers.

02

Least privilege for non-human identities

Scoped, short-lived, per-task credentials for agents — and an answerable blast-radius question for each one.

03

A curated dependency path

An internal registry that resolves what a model suggests against packages that actually exist and are actually vetted.

04

Logged prompts, tool calls and egress

If an agent acts, we need the trace — otherwise incident response has nothing to reconstruct.

05

A human gate on irreversible actions

Production deploys, payments, data deletion, permission changes: an agent proposes, a person approves.

Sequence

The first ninety days

Days 1–30

See the estate

Inventory every model, agent and AI tool in use — sanctioned or not. Name one accountable owner for the programme.

Days 31–60

Cut the blast radius

Re-scope agent credentials to least privilege. Put a human gate on irreversible actions. Publish one approved-tool path.

Days 61–90

Close the loop

Turn on tool-call and egress logging. Wire the CRA reporting path end to end. Report coverage to the board each quarter.

Two metrics tell us whether this is working: what share of AI systems are in the inventory, and what share of agent credentials are scoped and short-lived.
