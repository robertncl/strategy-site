Choosing an AI gateway:
the 2026 market, scored against our stack

Every serious AI platform now puts a gateway between apps and models — one control point for identity, spend, and governance. This deck maps the top products and scores them against the three requirements that matter here:

  • Enterprise access control with Microsoft Entra ID
  • GitHub Copilot integration (BYOK)
  • Azure AI Foundry models

One API, many models

Identity & access

SSO for humans, OIDC/JWT for workloads, per-team virtual keys — no raw provider keys in app code, ever.

Budgets & quotas

Token limits, rate limits, and cost attribution per user, team, and application — chargeback becomes a query, not a project.

Observability

Every prompt, completion, latency, and cost in one audit trail — the evidence base for governance and incident response.

Guardrails

PII redaction, content safety, jailbreak detection, and policy checks applied in-line at the choke point rather than per app.

Resilience

Retries, fallbacks across deployments and regions, load balancing, and semantic caching — reliability engineering done once.

Our bar

Three requirements, and what “good” looks like

These are the filters applied to every product in this deck.

Requirement 1

Enterprise access control with Microsoft Entra ID

Entra must govern both planes of the gateway — the people who administer it and the workloads that call it.

  • Control plane: SSO (OIDC/SAML) into the gateway console, ideally with SCIM provisioning and Entra-group-to-team mapping.
  • Data plane: JWT validation of Entra-issued tokens on model traffic, so access is role-based rather than static-API-key-based.
  • Backend: managed identity from the gateway to Azure model endpoints — no provider keys stored anywhere.
Requirement 2

GitHub Copilot integration (BYOK)

Since 2025 Copilot supports bring-your-own-key: pointing chat and agent sessions at your own model endpoint — Azure OpenAI, Microsoft Foundry, Anthropic, or any OpenAI-compatible gateway. In June 2026 GitHub extended BYOK to the Copilot coding-agent app, and an enterprise-grade BYOK policy for organizations is in public preview. Routing Copilot through the gateway gives you audit, budgets, and data-boundary control over IDE AI traffic.

  • Good: a first-party, documented Copilot BYOK integration (Kong and TrueFoundry publish one; LiteLLM documents the VS Code proxy-override pattern).
  • Acceptable: any spec-faithful OpenAI-compatible endpoint — Copilot BYOK accepts a custom base URL and key.
Caveat: Copilot still applies strict hostname validation for some provider types, which can block gateway-fronted endpoints that impersonate a specific provider API; an open GitHub community discussion tracks relaxing this for regulated, zero-trust architectures. The OpenAI-compatible path is the reliable one today.
Requirement 3

Azure AI Foundry models

Foundry (which absorbed Azure OpenAI) is where our models live — GPT, Claude, Llama, Mistral, DeepSeek and the rest of the catalog. The gateway must treat it as a first-class provider.

  • Native provider support for Foundry model deployments, not a generic HTTP passthrough.
  • Managed-identity authentication to Foundry endpoints.
  • Notable: Foundry now ships a built-in “AI Gateway” configuration that is Azure API Management under the hood — Microsoft's own answer to this requirement.

Verdict

Recommendation

Five products clear all three requirements. For an Entra-governed, Foundry-hosted, Copilot-consuming estate, the shortlist orders itself:

1 · Primary

Azure APIM AI Gateway

Azure-native on all three requirements with zero new vendors; it is literally the engine of Foundry's own gateway feature — and the architecture we've already designed.

2 · If OSS control matters

LiteLLM

Deepest provider coverage and community; Entra SSO, JWT auth and group sync at enterprise tier. Run it behind APIM or standalone in AKS.

3 · If buying, not building

Portkey

Best managed enterprise story: Azure Marketplace deploy, Entra SSO + SCIM, built-in guardrails and audit. Enterprise plan required for the identity features.

Situational

Kong / TrueFoundry

Both publish official Copilot BYOK integrations — first choice if Kong already fronts your APIs, or if you want one gateway spanning LLM + MCP + agents on AKS.

The pattern, whichever product wins

Copilot (BYOK) · apps · agents → Entra ID token → AI Gateway → managed identity → Azure AI Foundry models

Callers — including Copilot pointed at the gateway's OpenAI-compatible endpoint — authenticate with Entra-issued credentials; the gateway enforces roles, budgets, and guardrails, then reaches Foundry with a managed identity. No raw model keys leave the platform team. Watch two moving parts: GitHub's enterprise BYOK policy (public preview) and the hostname-validation limits on provider-impersonating endpoints.
