Definitions / chatbot vs agent

An agent doesn't just answer.
It gets things done.

A chatbot talks. An agent plans a task, uses your real tools to carry it out, checks the result, and comes back when it's done — or when it needs you. That last part is the point: you stay in the loop, approving anything that matters.

Chatbot

Suggests

"Here's a draft reply you could send."

Agent

Acts

Drafts the reply, files the Jira ticket, waits for your OK to send.

The four moves every agent makes

Plan → Use tools → Check → Report back

It breaks the goal into steps, calls into Jira, Outlook or Excel to do the work, verifies the output, and surfaces anything needing a human decision.

Guardrails / do this before you scale

Move fast, but keep the brakes.

Keep a human on the trigger

Agents can draft, sort and summarise freely. Sending, posting, paying or deleting always waits for a person to click approve.

Least-privilege access

Give each agent its own account with only the permissions that one job needs — not your personal admin rights.

Keep company data inside the tenant

Use your M365 and Atlassian connections so data never leaves approved systems. Confirm licensing with IT first.

Log what it does & name an owner

Every agent keeps a run history and has one person responsible. If it drifts, you can see why and switch it off.
